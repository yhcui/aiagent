# Haven · 个人工作台 产品规划

> 最后更新：2026-09-03

## 一、产品定位

**Haven** 是一个面向个人的轻量级工作台应用，聚合日常创作、灵感记录、任务管理等碎片化需求于一处，提供温暖、私属、专注的个人空间。

- **产品名**：Haven（避风港/栖息地）
- **定位**：个人工作台（Personal Workspace）
- **愿景**：一处温暖、有序、随想随记的个人空间，让灵感与待办不再散落
- **气质**：温暖友好 · 柔和配色 · 圆角设计 · 适合创意工具

## 二、核心原则

1. **极简优先**：单个功能做到极致好用，不堆砌冗余字段
2. **可扩展架构**：模块化设计，新功能以"工作台模块"形式接入，互不干扰
3. **温暖陪伴**：视觉柔和、交互细腻、动效轻盈，避免冷冰冰的工具感
4. **本地优先**：SQLite 单文件存储，数据自掌握，无需账户体系
5. **单页聚焦**：每个功能在单一页面内完成核心闭环，降低认知负担

## 三、技术栈

| 层 | 技术选型 | 说明 |
|----|---------|------|
| 前端框架 | React 18 + Next.js 14 (App Router) | 全栈一体，路由即模块 |
| 样式方案 | Tailwind CSS | 原子化，快速实现温暖配色与圆角 |
| 数据库 | SQLite (better-sqlite3) | 单文件存储，零运维 |
| ORM | Drizzle ORM | 轻量、类型安全、原生支持 SQLite |
| 状态管理 | React Server Components + 本地 useState | 路由级即数据边界，减少客户端状态 |
| 动效 | Framer Motion | 列表增删的细腻过渡 |
| 语言 | TypeScript | 全量类型安全 |
| 包管理 | pnpm | 快速、省磁盘 |

```
│   ├── lib/

│   │   │   ├── index.ts       # 连接实例
│   │   │   └── schema.ts      # Drizzle 表定义

├── public/                    # 静态资源
├── data/

├── drizzle.config.ts          # Drizzle 配置
├── next.config.mjs
├── tailwind.config.ts
├── tsconfig.json
├── package.json

```

**结构说明**：
- `features/` 按业务模块组织，未来新增功能（如笔记、待办、读书等）各自独立成目录，互不耦合
- `components/ui/` 存放与业务无关的原子组件，跨模块复用
- `lib/db/schema.ts` 统一管理所有表定义，新模块加表只在此文件追加
- `app/` 路由与 `features/` 一一对应，路由层薄、业务逻辑下沉到 features

## 五、数据库设计

### 表结构预留扩展

采用统一的表设计风格，所有业务表都以"轻量内容卡片"形态存在，方便未来不同模块复用模式。

#### 1. ideas 表（Idea 管理）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| content | TEXT NOT NULL | Idea 内容 |
| is_completed | INTEGER DEFAULT 0 | 完成状态（0 未完成 / 1 已完成）|
| created_at | TEXT | 创建时间（ISO 8601）|
| completed_at | TEXT | 完成时间（可空）|

> 采用 TEXT 存时间，避免 SQLite 时区与序列化坑；前端展示时格式化。

#### 2. 扩展预留

未来新增模块（笔记、待办、收藏等）时，建议各自独立建表，保持单表职责单一，避免过早抽象导致的耦合。

## 六、首期功能：Idea 管理

### 6.1 功能清单

| 操作 | 说明 |
|------|------|
| 添加 | 页面顶部输入框，回车或点击按钮提交 |
| 查看 | 列表形式展示所有 idea |
| 完成 | 点击 idea 左侧圆形按钮切换完成状态 |
| 删除 | hover 出现删除按钮，二次确认防误删 |
| 排序 | 未完成在前，已完成在后；同组内按创建时间倒序 |

### 6.2 排序规则

```
未完成组（按 created_at 倒序）
  ↓
已完成组（按 completed_at 倒序）
```

### 6.3 交互细节

- 输入框常驻顶部，支持回车快速提交，提交后清空并自动聚焦
- 完成的 idea 文字加删除线、变灰，与未完成项视觉区隔
- 删除前弹出轻量确认气泡（不阻塞、可撤销思路）
- 列表新增/删除/完成均有 Framer Motion 过渡动效
- 空状态：温暖插画 + 文案"记下第一个想法吧 ✨"

## 七、UI / UX 设计

### 7.1 配色（温暖友好）

| 角色 | 色值 | 用途 |
|------|------|------|
| 背景主色 | `#FBF7F0`（暖白米）| 页面背景 |
| 卡片色 | `#FFFFFF` | 卡片/输入框背景 |
| 主强调 | `#E8A87C`（柔和橘）| 主按钮、强调元素 |
| 辅强调 | `#C38D9E`（柔粉紫）| 完成态、次要强调 |
| 文字主色 | `#3D3D3D` | 主要文字 |
| 文字辅色 | `#8B8B8B` | 次要文字 |
| 成功色 | `#85B79D`（薄荷绿）| 完成态背景点缀 |

### 7.2 设计规范

- **圆角**：卡片 `rounded-2xl`（16px）、按钮 `rounded-xl`（12px）、输入框 `rounded-xl`
- **阴影**：柔和浅阴影 `shadow-sm` + hover 时 `shadow-md`，避免重阴影
- **间距**：基础单位 4 的倍数，列表项间距 12px
- **字体**：系统默认无衬线 + 中文优先 `"PingFang SC", "Microsoft YaHei"`
- **图标**：Lucide React，线条圆润统一
- **动效**：时长 200-300ms，缓动函数 `ease-out`，轻量不抢戏

### 7.3 布局

- **桌面端**：左侧固定窄侧边栏（导航 + Logo）+ 右侧主内容区，内容区最大宽度 720px 居中
- **移动端**：侧边栏收起为底部 Tab，内容区全宽
- **首屏**：单页聚焦 Idea 管理，无需分页（数据量小，未来再考虑虚拟滚动）

## 八、可扩展性设计

### 8.1 模块接入约定

未来新增功能模块时，遵循统一约定：

1. 在 `src/features/{模块名}/` 下创建 `components/`、`actions.ts`、`queries.ts`
2. 在 `src/app/{模块名}/page.tsx` 创建对应路由页面
3. 在 `src/lib/db/schema.ts` 追加新表定义
4. 在侧边栏导航配置中注册菜单项

### 8.2 通用能力沉淀

随着功能增多，逐步将重复模式抽取为通用能力：
- 通用 CRUD Server Action 工厂
- 通用列表组件（支持空状态、加载、动效）
- 通用确认气泡组件

> 原则：**先复制，后抽象**，避免过早抽象导致过度设计。

## 十、非功能要求

- **性能**：首屏 SSR 渲染，交互通过 Server Actions 减少客户端 JS
- **可维护性**：TypeScript 全量类型，模块边界清晰
- **可移植**：SQLite 单文件，整个项目可打包迁移
- **无账户**：个人本地使用，暂不做登录与多用户
