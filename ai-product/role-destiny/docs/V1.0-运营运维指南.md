#### 数据查看方式

**方式一：数据库直接查询（推荐开发提供简单后台）**

```sql
-- 昨日核心数据汇总
SELECT 
  DATE(created_at) as date,
  COUNT(DISTINCT user_id) as new_users,
  COUNT(*) as total_tests,
  SUM(CASE WHEN is_paid = 1 THEN 1 ELSE 0 END) as paid_count,
  ROUND(SUM(CASE WHEN is_paid = 1 THEN 0.99 ELSE 0 END), 2) as revenue
FROM user_tests 
WHERE DATE(created_at) = CURDATE() - INTERVAL 1 DAY
GROUP BY DATE(created_at);

-- 各角色分布（了解哪个角色最受欢迎）
SELECT 
  r.name as role_name,
  COUNT(*) as count,
  ROUND(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM user_tests WHERE DATE(created_at) = CURDATE() - INTERVAL 1 DAY), 2) as percentage
FROM user_tests ut
JOIN roles r ON ut.result_role_id = r.id
WHERE DATE(ut.created_at) = CURDATE() - INTERVAL 1 DAY
GROUP BY r.id
ORDER BY count DESC;

-- 付费转化漏斗
SELECT 
  '发起测试' as stage,
  COUNT(*) as count
FROM user_tests WHERE DATE(created_at) = CURDATE() - INTERVAL 1 DAY
UNION ALL
SELECT 
  '完成测试',
  COUNT(*)
FROM user_tests WHERE DATE(created_at) = CURDATE() - INTERVAL 1 DAY AND status = 'completed'
UNION ALL
SELECT 
  '付费用户',
  COUNT(*)
FROM user_tests WHERE DATE(created_at) = CURDATE() - INTERVAL 1 DAY AND is_paid = 1;
```

```
数据异常？
    │
    ├─▶ 访问量骤降
    │     ├─ 检查小程序是否被搜到（搜索排名）
    │     ├─ 检查分享链接是否正常

    ├─▶ 付费率骤降
```

#### 内容更新频率与规范

| 内容类型 | 更新频率 | 更新时机 | 注意事项 |
|---------|---------|---------|---------|
| **题目文案** | 按需（每月1-2次） | 发现某题选择过于集中时 | 保持趣味性，避免敏感词 |
| **角色文案** | 按需（每月1-2次） | 用户反馈"不准"较多时 | 文案要走心，有共鸣感 |
| **封面/配图** | 按需 | 节日热点、季节变化 | 图片风格统一 |
| **海报模板** | 按需 | 分享率下降时 | A/B测试不同风格 |
| **新增测试主题** | 每2-4周一次 | 第一个主题跑通后 | 确保质量再上线 |

#### 内容审核检查清单

每次内容更新后，必须检查：

- [ ] 所有文字无错别字
- [ ] 无敏感词汇（政治、色情、暴力等）
- [ ] 无侵权风险（不使用具体IP角色名）
- [ ] 各选项的得分逻辑合理（不会导致某个角色概率过高）
- [ ] 在真机上完整测试一遍流程
- [ ] 支付金额正确（¥0.99）
- [ ] 海报生成正常且美观

- 描述可以泛化：「如果你穿越到古代宫廷...」

### 4.2 常见问题及标准回复

#### Q1：付费了但没看到完整结果

**可能原因**：
1. 支付成功但回调延迟
2. 网络问题导致页面未刷新
3. 极少数情况：订单状态未正确更新

**处理步骤**：
1. 先安抚用户："抱歉给您带来不便，我马上帮您查询"
2. 在后台查询用户的订单状态和测试记录
3. 如果已付款但未解锁：手动帮用户解锁，并致歉
4. 如果确实未付款：礼貌说明，请用户核实

**标准回复话术**：
```
亲，抱歉让您久等了！我已经帮您查询了订单记录，
确认您的支付已经成功。可能是网络延迟导致页面没有及时更新。

请您重新进入小程序 → 点击「我的」→ 找到之前的测试记录，
现在应该可以看到完整结果了。

如果还有问题，请随时告诉我，我会第一时间帮您解决！🙏
```

#### Q2：觉得测试结果不准确

**处理原则**：
1. 先倾听用户的具体感受
2. 不要争辩，表示理解
3. 解释测试的娱乐性质
4. 引导用户重新测试（增加粘性）

**标准回复话术**：
```
亲，感谢您的反馈呢！😊

这个测试是基于您选择的答案进行匹配的，
有时候心情不同选的选项不一样，结果也会有所不同哦~

如果您觉得这次的结果不太像您，不妨换个心情再测一次，
说不定会有新的发现！而且第二次测试可能会有不同的体验呢~

当然啦，这毕竟是个趣味小测试，娱乐为主，
希望您玩得开心最重要！💕
```

#### Q3：要求退款

**退款政策建议**：

| 场景 | 是否退款 | 说明 |
|-----|---------|------|
| 重复支付 | ✅ 退 | 系统bug导致 |
| 误操作支付 | ✅ 可退 | 首次可酌情处理 |
| 对结果不满意 | ❌ 不退 | 属于虚拟内容，已消费 |
| 技术故障无法使用 | ✅ 退 | 无法提供服务的情况 |

**标准回复话术（拒绝退款）**：
```
亲，非常理解您的想法呢！

不过因为我们的测试结果是即时生成的虚拟内容，
在您付费查看后就已经完成了服务交付，
所以暂时无法支持退款哦，望您谅解~🙏

如果您对这次的测试结果不太满意，
欢迎随时免费重新测试其他主题（后续会持续上新），
或者把您的想法告诉我们，我们会不断优化的！

再次感谢您的支持！❤️
```

#### Q4：建议增加新的测试主题

**处理方式**：
1. 感谢用户的建议
2. 记录下来（建立需求池）
3. 告知大概的上新时间
4. 可邀请用户参与内测

**标准回复话术**：
```
哇，这个主意太棒了！🌟 感谢您的创意建议！

我们已经把这个想法记录下来了，
目前正在筹备新的测试主题，预计xx月会上线哦~

到时候如果您愿意的话，可以邀请您抢先体验内测版，
给我们提提意见！请关注我们的更新通知吧~

再次感谢您的支持和喜爱！💕
```

## 六、异常事件处理手册

### 6.1 技术类异常

#### 支付异常

| 症状 | 可能原因 | 处理方式 | 升级条件 |
|-----|---------|---------|---------|
| 用户扣款但未到账 | 回调延迟/失败 | 手动查询订单并补发 | 单日>5例 |
| 支付按钮点击无反应 | 前端bug | 收集机型信息，反馈技术 | 普遍性问题 |
| 支付金额错误 | 配置错误 | 立即下线修复 | 任何情况 |

**应急处理流程**：
```
收到支付异常投诉
    ↓
1. 安抚用户，记录问题（用户ID、订单号、金额、时间）
    ↓
2. 后台查询订单状态
    ↓
3. 如果确实已扣款未到账 → 手动解锁 + 致歉 + 小红包补偿（可选）
    ↓
4. 统计当日此类问题数量
    ↓
5. 如果≥3例 → 立即报告技术团队排查
    ↓
6. 如果是普遍性问题 → 考虑暂时下线支付功能
```

#### 接口异常

| 症状 | 处理方式 |
|-----|---------|
| 小程序打不开 | 检查服务器状态，联系运维 |
| 测试加载不出来 | 检查API是否正常，刷新CDN缓存 |
| 海报生成失败 | 暂时关闭海报功能，引导用户截图分享 |
| 数据丢失 | 从备份恢复，联系技术 |

### 6.2 内容类异常

#### 敏感内容投诉

**症状**：用户投诉内容不当、违规等

**处理流程**：
```
收到内容投诉
    ↓
1. 立即查看被投诉的具体内容
    ↓
2. 判断是否真的有问题
    ├─ 是 → 立即修改/下线 + 回复用户 + 记录
    └─ 否 → 礼貌解释 + 记录（避免争议）
    ↓
3. 分析原因（是文案问题还是用户误解？）
    ↓
4. 优化内容审核流程，避免再犯
```

#### 版权风险预警

**症状**：收到律师函、平台下架通知、权利人投诉

**处理流程**：
```
收到版权警告
    ↓
1. 立即停止相关内容的展示和使用
    ↓
2. 保留所有证据（截图、通信记录）
    ↓
3. 立即报告负责人 + 法务（如有）
    ↓
4. 评估风险，决定是否需要：
   - 正式道歉
   - 内容整改
   - 法律应对
    ↓
5. 全面自查所有内容，确保无类似问题
```

### 6.3 运营事故分级

| 级别 | 定义 | 示例 | 响应时间 | 处理人 |
|-----|------|------|---------|-------|
| **P0 紧急** | 核心功能不可用 | 支付全挂、数据丢失 | 5分钟内 | 技术+产品 |
| **P1 严重** | 主要功能受损 | 部分用户无法支付、海报生成失败 | 30分钟内 | 技术+运营 |
| **P2 一般** | 影响部分体验 | 加载稍慢、个别文案错误 | 2小时内 | 运营 |
| **P3 轻微** | 小问题 | 错别字、图片不够精美 | 24小时内 | 运营 |

### 7.2 关键分析方法

#### 漏斗分析法

用于找出转化流失的关键环节：

```
用户旅程漏斗：

100% 开始测试
  ↓ 85%（流失15%）
85% 完成答题
  ↓ 95%（流失5%）
81% 到达结果页
  ↓ 25%（流失75%）← 关键流失点！
20% 点击付费
  ↓ 75%（流失25%）
15% 支付成功
  ↓
15% 查看完整结果
  ↓ 50%（流失50%）
7.5% 生成海报
  ↓
2.25% 实际分享
```

**优化方向**：
- 如果「开始测试→完成答题」流失高 → 题目太长/太难/无聊
- 如果「到达结果页→点击付费」流失高 → 预览不够吸引/价格太高
- 如果「点击付费→支付成功」流失高 → 支付流程有问题

#### 同比环比分析

- **同比**：和上周比（看趋势）
- **环比**：和昨天比（看短期波动）
- 关注异常波动（超过±20%需要关注原因）

#### 用户分群分析

| 分群维度 | 分析目的 |
|---------|---------|
| 新老用户 | 老用户复购率如何？（V1.0主要看新用户） |
| 付费/未付费 | 两拨人的行为差异在哪？ |
| 分享/未分享 | 分享用户有什么特征？ |
| 不同角色 | 哪个角色最受欢迎？是否需要调整？ |

## 九、合规与风控

### 9.1 内容合规红线

**绝对不能碰的红线**：

| 类别 | 具体内容 | 风险等级 |
|-----|---------|---------|
| **政治敏感** | 涉及国家领导人、政治体制、领土问题 | 🔴 致命 |
| **色情低俗** | 暴力、色情、赌博相关 | 🔴 致命 |
| **侵权内容** | 直接使用他人IP、未经授权的内容 | 🔴 致命 |
| **虚假宣传** | 夸大效果、承诺不可能的事 | 🟡 高 |
| **诱导分享** | 强制分享才能看结果（微信禁止） | 🟡 高 |
| **收集隐私** | 过度收集用户信息 | 🟡 高 |
| **虚假评价** | 刷好评、刷数据 | 🟠 中 |

### 9.2 微信小程序运营规范要点

1. **不得强制授权**：不能一进来就弹授权，要让用户主动触发
2. **不得诱导分享**：不能用"分享后解锁"这类文案
3. **不得过度营销**：推送消息频率有限制
4. **内容必须真实**：不能夸大效果（如"100%准确"）
5. **支付必须明确**：价格、商品描述必须清晰

### 9.3 定期自查清单

建议每周进行一次快速自查：

- [ ] 小程序能正常打开和使用
- [ ] 支付功能正常
- [ ] 所有文案无敏感词
- [ ] 无侵权内容
- [ ] 用户隐私政策最新
- [ ] 客服联系方式有效
- [ ] 分享功能正常
- [ ] 数据统计正常上报
